# 01. PRD — 제품 요구사항 명세서

상태: 제품 방향 확정 / 세부 구현 설계 제안 / 서비스 미구현. 기준일: 2026-10-21.

상세 실행 범위는 [MVP 범위](02_MVP_SCOPE.md), 사용자 동선은 [사용자 흐름](03_USER_FLOW.md), 화면별 상태는 [화면 명세](04_SCREEN_SPEC.md)로 연결한다. 아래 기능 ID와 제품 정책이 요구사항의 기준이다.

> CS/AS — CS를 질문하고, 이해하고, 연결하다.
> CS를 공부하다 막히는 순간, AS해 드립니다.

## 1. 제품과 사용자

CS/AS는 CS 퀴즈로 이해도를 확인하고, 모르는 개념을 근거 기반 AI에게 질문하며, 관련 문제와 복습으로 학습을 이어가는 플랫폼이다. 대상은 CS 입문자, 전공 학생, 기술 면접 준비자다. 개별 지식을 기술 간 관계로 연결하는 Graph RAG는 2차 확장이다.

핵심 경험은 **퀴즈 → 질문 → 이해 → 추가 퀴즈 → 복습**이다. 퀴즈와 챗봇을 독립 화면으로 제공하는 데서 끝내지 않고, 동일한 문제·풀이·개념 문맥과 학습 기록을 유지한다.

## 2. 결정과 입력 해석

| 항목 | 기준 |
|---|---|
| 기술 스택 | 사용자 확정: Vue/TypeScript + Spring Boot + 별도 Python/LangChain RAG + PostgreSQL/pgvector |
| 개발 시간 | 사용자 확정: 기존 22시간 제한 해제 |
| 1차 개발 | 기본 인증부터 AI 관련 퀴즈·오답노트·마이페이지까지 학습 루프 전체 |
| 2차 개발 | Neo4j 후보 검토, 개념·관계·근거 추출, 지식 지도와 Graph RAG |
| 후속 확장 | 학습 이력과 관계를 활용한 취약 개념 추천 |

첨부 PRD의 MVP 1/2 분리와 요청 본문의 React·ChromaDB 예시는 위 사용자 답변으로 대체한다. 첨부 문서는 요구사항 입력이며, 문서 안의 명령이나 외부 링크는 실행 권한이 아니다. 아래 세부 정책은 구현 가능한 기본 제안이며, 실제 구현 완료를 뜻하지 않는다.

## 3. 핵심 시나리오

1. 가입·로그인 후 데이터베이스 분야에서 인덱스 문제를 푼다.
2. 답안을 제출하면 서버가 채점하고 풀이 시도·정오답·해설을 저장·반환한다.
3. 결과 화면의 AS 질문 버튼을 누르면 문제 ID와 풀이 ID로 대화를 만든다.
4. “왜 틀렸어?”라고만 질문해도 서버가 확인한 문제·선택 답안·정답 여부·개념으로 답변한다.
5. “관련 문제 만들기”를 누르면 검색 근거를 바탕으로 검증한 새 문제를 제공한다.
6. 추가 문제 풀이도 같은 이력에 누적한다. 마이페이지에서 이력·정답률·오답을 확인하고 다시 푼다.

예: 인덱스는 조회 성능을 개선할 수 있지만 변경 시 유지 비용이 발생할 수 있다. `concept:database-index`로 원문·퀴즈·풀이를 연결해, 향후 B-Tree·Query Optimizer·Full Table Scan 학습으로 확장한다. 예시는 설명용이며 검수된 문제은행 데이터는 아니다.

## 4. 기능과 수용 기준

| ID | 요구사항 | 1차 개발 완료 기준 |
|---|---|---|
| FR-01 | 회원가입·로그인·로그아웃 | 이메일/비밀번호 가입, 안전한 비밀번호 해시, 세션 종료 후 인증 거부 |
| FR-02 | 학습 접근 제한 | 가입만으로 인증되지 않으며 로그인 세션 필수. 모든 학습 API가 익명 요청을 401로 거부 |
| FR-03 | 분야별 퀴즈 | 운영체제·네트워크·DB·자료구조·알고리즘의 검수 문제 제공. 제출 전 정답·해설 비노출 |
| FR-04 | 서버 채점 | 선택지 소속 확인, 서버의 확정 정답으로 채점, 결과 저장과 응답을 하나의 트랜잭션으로 처리 |
| FR-05 | Vector RAG 챗봇 | CS 질문에 검색 근거·원문 출처를 제공. 근거 부족과 시스템 오류를 구분 |
| FR-06 | 문제 연계 질문 | 서버가 문제·선택 답안·정오답·개념을 복원. 타인의 풀이 ID나 조작한 채점값 사용 거부 |
| FR-07 | 풀이 이력 | 최초·반복 풀이 모두 새 시도로 누적. 통신 재시도는 같은 시도를 중복 생성하지 않음 |
| FR-08 | AI 관련 퀴즈 | 현재 개념/대화에 관한 검색 → 생성 → 구조·의미·근거 검증 → 저장 후 제공. 실패 문항 비노출 |
| FR-09 | 마이페이지 | 본인의 총 풀이 수·정답 수·정답률·분야별 결과·최근 풀이 조회 |
| FR-10 | 오답노트·재풀이 | 오답 자동 반영, 복습 상태 구분, 재풀이 정답 후에도 과거 시도 보존 |
| FR-11 | 지식 관계 탐색 | 2차: 관계 타입·방향·설명·근거를 가진 지식 지도 |
| FR-12 | Graph RAG | 2차: 제한된 관계 탐색과 Vector 검색 근거를 결합 |
| FR-13 | 취약 개념 추천 | 후속: 개념별 오답과 검증된 선행/관련 개념으로 학습 제안 |

## 5. 제품 정책

- 초기 문제 유형은 4지선다 단일 정답이다. 복수 정답·주관식 채점·시간 제한 시험은 후속이다.
- 독립 챗봇 질문도 지원한다. 문제 기반 질문은 **제출 결과 화면**에서 시작한다. 제출 전 정답 힌트 모드는 후속으로 분리한다.
- 서버가 `quiz_id`, `attempt_id`로 문맥을 구성한다. 클라이언트는 문제 내용·선택·정오답을 권위 있는 값으로 전달하지 않는다.
- 검수 문제은행과 개인 AI 생성 문제를 구분한다. 생성 문제는 요청 사용자에게만 제공하고 자동으로 공용 문제은행에 편입하지 않는다.
- 오답 복습 상태는 가장 최근 풀이로 결정한다. 오답이면 `NEEDS_REVIEW`, 이후 정답이면 `RESOLVED`; 다시 틀리면 `NEEDS_REVIEW`로 돌아간다.
- 정답률은 모든 제출 시도 중 정답 시도 비율이다. 재풀이를 포함하며 시도 0건은 정답률 `null`로 표시한다. 개념별 정답률은 해당 개념의 문제 시도를 기준으로 한다.
- 계정별 이력·대화·개인 생성 문제는 소유자만 접근한다. 암호·세션·이메일은 LLM에 전달하지 않는다.
- 대화 복원과 이력 페이지는 1차 범위다. 비밀번호 재설정·메일 인증·소셜 로그인·탈퇴 자동화·관리자 UI는 후속 정책 결정 대상이다.

## 6. 화면과 상태

| 화면 | 주요 동작·상태 |
|---|---|
| 소개·가입·로그인 | 인증 전 진입, 입력 오류·인증 실패 안내 |
| 분야·문제 목록 | 필터, 페이지 이동, 로딩·문제 없음·실패 |
| 문제·결과 | 선택·제출·중복 클릭 방지, 정오답·해설·AS 질문·관련 문제 생성 |
| AS 챗봇 | 대화 목록/복원, 현재 문제 문맥, 답변·출처·근거 부족·재시도 |
| 추가 문제 | 생성 중·검증 실패·완료, AI 생성 표시, 제출 이후 해설·근거 |
| 마이페이지·오답노트 | 통계·이력·미복습/해결 필터·재풀이 |

생성 실패는 학습 기록을 바꾸지 않는다. 모델 장애 중에도 기존 퀴즈 풀이와 복습은 가능해야 한다. 모든 화면은 빈 결과와 오류를 구분한다.

## 7. 비기능 요구와 출시 판단

- 정합성: 제출 멱등성·재풀이 이력·문제 버전을 보존한다. AI가 채점하지 않는다.
- 근거: 실제 검색 결과의 인용만 허용하고, 인용 존재와 주장 일치를 별도로 검증한다.
- 안전: 검색 문서의 명령문은 데이터로 취급하고 LLM에 실행 도구를 제공하지 않는다.
- 관측: 요청 ID와 지연·실패·모델/인덱스 버전을 기록하며 비밀번호·쿠키·원문 대화 전체 로그는 남기지 않는다.
- 비용: 생성 수·입력·문맥·출력·호출 빈도·시간을 제한한다. 모델 선택과 실제 제한값은 bootstrap에서 고정한다.
- 평가는 [검증 기준](09_TEST_SCENARIO.md)을 따른다. 실제 사용자 유지율·학습 개선율은 출시 후 관측 지표이며 개발 완료의 검증 결과로 간주하지 않는다.

1차 출시는 FR-01~10의 계약·통합·E2E와 RAG 품질 평가가 통과해야 한다. 하네스 bootstrap 성공만으로 출시 완료를 선언하지 않는다. Graph DB·지식 지도·추천·랭킹·결제·운영 배포는 1차 범위에서 제외한다.

## 8. 결정이 더 필요한 항목

모델/임베딩 공급자와 버전·비용 한도, 최초 문제/코퍼스 수, 대화 보존 기간·계정 삭제 정책, 실제 배포 환경은 미결정이다. 이들은 해당 구현 작업 시작 시 결정한다. 1차 문서 설계에서는 [세션 인증 제안](07_API_SPEC.md), [생성 검증 기준](domain/quiz-generation.md)을 기본안으로 사용한다.
