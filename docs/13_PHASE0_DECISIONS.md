# 13. PHASE 0 DECISIONS — 사전 설계 결정

상태: 제품 범위·스택 채택 / 세부 설계 제안. 결정일: 2026-10-21.

기존 ADR 0003의 식별자와 결정 이력을 유지하며 Phase 0 기준 문서로 사용한다. 모델·버전·초기 데이터 수·보존/배포 정책은 미결정이다. 역할별 책임은 [11_TEAM_OWNERSHIP](11_TEAM_OWNERSHIP.md)의 논리 분장이고 실제 팀원 배정은 아니다.

## 배경과 근거

기존 문서는 질문·검색·출처 표시만 22시간 MVP로 정의했다. 사용자 요청은 퀴즈·질문·추가 문제·복습을 연결하는 학습 플랫폼이다. 첨부 PRD와 요청 본문에 React/ChromaDB 및 단계별 MVP 예시가 있었으므로 확인 질문을 진행했다.

사용자 답변:
- “기존 Vue + Spring Boot + Python RAG + PostgreSQL/pgvector 유지”
- “22시간 제한 없이 학습 루프 전체를 1차 목표로 설계”

## 결정

1. [PRD](01_PRD.md)의 FR-01~10을 1차 개발 범위로 한다. 구현 순서는 나누지만 일부 단계 완료를 전체 학습 루프 완료로 간주하지 않는다.
2. Vue/TypeScript, Spring Boot, 별도 Python/LangChain 프로세스, PostgreSQL/pgvector를 유지한다. ChromaDB·React 전환은 진행하지 않는다.
3. PostgreSQL 서비스 데이터와 RAG 검색 데이터의 역할·소유권을 분리한다. 퀴즈 정답은 서버 DB로 채점한다.
4. 공통 concept_id를 퀴즈·문서·청크·향후 그래프에 사용한다.
5. Graph RAG는 2차다. Neo4j는 후보이고 필수 의존성은 도입하지 않는다. 관계 의미·근거·검증을 선행한다.

## 세부 설계 기본안

동일 출처 프록시를 사용하는 쿠키 세션 인증, 제출 후 문제 질문, 4지선다 1문항 생성, 개인 생성 문제, 동기 내부 RAG HTTP, 불변 문제 버전·풀이 이력을 제안한다. 이 기본안은 사용자 확정 스택과 구분하며 구현 시 필요한 근거·검사·운영 조건을 기록한다.

## 대안과 영향

- React/ChromaDB 또는 FastAPI 단일 백엔드: 기존 영역별 구조와 다른 전환 비용이 있어 사용자 선택에 따라 제외했다.
- 인증·기록을 제외한 RAG 단독 MVP: 제품의 학습 흐름을 검증하지 못하므로 전체 출시 목표로 쓰지 않는다.
- Graph 동시 구현: 1차 학습 기능과 데이터 품질 검증을 복잡하게 하므로 연기한다.

ADR 0002의 경로/영역별 진입점은 유지하며 도메인을 학습 영역으로 확장한다. 기존 001 계획의 결과는 역사적 기록이다. 기존 machine-readable task의 “인증 제외”·평가 항목은 새 제품과 다르므로 [하네스 연계 문서](harness-workflow.md)에 전환 작업을 명시한다. 이번 작업에서는 하네스 정책을 수정하지 않는다.

## 검증

문서 링크·공개 API 참조/권한·기능 ID의 설계/검사 연결을 확인한다. 실제 구현은 [검증 기준](09_TEST_SCENARIO.md)과 후속 계획을 만족해야 한다. 버전·모델·보존 정책은 bootstrap/배포 전 별도 결정한다.
